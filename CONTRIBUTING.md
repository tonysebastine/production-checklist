# Contributing

1. Open an issue for significant changes and describe the operational or security problem.
2. Keep checklist items actionable and testable.
3. Include verification steps and the evidence required to mark a control Pass.
4. State applicability assumptions and operational impact.
5. Never commit secrets, customer data, internal IPs, or sensitive logs.
6. Review commands for destructive side effects before submitting.

Suggested item format:
- [ ] **Control:** specific action or condition.
  - **Evidence:** test result, configuration review, command output, or ticket.
  - **Owner:** accountable role.
  - **Failure impact:** security, integrity, availability, or compliance consequence.
