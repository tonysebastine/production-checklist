# Security Policy

## Reporting vulnerabilities
Do not publish exploitable details or secrets in a public issue. Use GitHub's private vulnerability reporting feature if enabled, or contact the repository maintainer privately. Include affected files/versions, impact, reproduction steps, and mitigation suggestions.

## Safe use
- Assess only systems you own or are explicitly authorized to test.
- Review commands before execution; environment-specific checks can disrupt production.
- Never commit credentials, tokens, private keys, personal data, or production database dumps.
- Checklist completion is evidence of specific checks, not a certification or guarantee of security.
